> **给 AI 工具（Cursor/Claude Code 等）执行**：你是团队管理员。按本清单把 team-memory 部署到团队 Gitea。**全团队只做一次**。遇到 `<占位符>` 时询问用户填入真实值，不要自行编造。
>
> 当前工具版本：**v0.2.2** · 配套文档：[Gitea 部署指南](Gitea本地部署与迁移指南.md) · [组员操作清单](组员操作清单.md)

## 一、系统架构（先理解再部署）

团队记忆系统由 **两个 Git 仓库 + 两个常驻服务** 组成：

```
┌─────────────────────────────────────────────────────────────┐
│  Gitea  http://<GITEA主机>:3000                             │
│  ├── ai-team/team-memory.git      ← 记忆数据（Markdown）   │
│  └── ai-team/agent-team-memory.git ← CLI/MCP 工具代码       │
└─────────────────────────────────────────────────────────────┘
         ▲ sync/push                              ▲ git pull
         │                                        │
┌────────┴────────┐                    ┌─────────┴──────────┐
│ 组员本机         │                    │ 共享服务器（可选）    │
│ ~/team-memory   │                    │ /data3/.../team-memory│
│ onboard + save  │                    │ Web :8765 (只启一次)  │
└─────────────────┘                    └──────────────────────┘
```

| 组件 | 路径/地址 | 谁写 | 谁读 |
|---|---|---|---|
| **记忆数据仓库** `team-memory` | `~/team-memory` 或共享盘 | 组员 `save` / `sync` | Web、skill、MCP |
| **工具仓库** `agent-team-memory` | clone 后 `pip install -e .` | 管理员发版 | 组员安装 CLI |
| **Gitea** | `:3000` | — | 全员 push/pull |
| **Web 可视化** | `:8765`（固定链接） | — | 全员浏览器 |

**铁律**：记忆 Markdown **只进** `team-memory` 仓库；**禁止**写进 `agent-team-memory/team_memory/`（那是 Python 源码目录）。

## 三、步骤 0 — 启动 Gitea（底座）

Gitea 必须先于记忆系统运行。任选 **Docker** 或 **原生二进制**（内网 CentOS 常用后者）。

### 方式 A：Docker Compose（推荐新环境）

见 [Gitea本地部署与迁移指南.md](Gitea本地部署与迁移指南.md) 第四节。关键点：

- `.env` 中 **`DB_TYPE=sqlite3`**（不能写 `sqlite`）
- 端口：`3000`（Web）、`2222`（Git SSH）

```bash
cd ~/gitea
docker compose up -d
curl -s -o /dev/null -w "HTTP %{http_code}\n" http://<GITEA主机IP>:3000/   # 期望 200
```

### 方式 B：原生二进制 + user systemd（当前生产示例）

```bash
# 初始化（仅首次）
cd /data/liw/gitea
bash setup-local.sh          # 生成 app.ini、管理员 liw、密码写入 .admin_password

# 注册常驻服务（liw 用户，无需 sudo）
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/gitea.service << 'EOF'
[Unit]
Description=Gitea local server
After=network.target
[Service]
Type=simple
WorkingDirectory=/data/liw/gitea
Environment=GITEA_WORK_DIR=/data/liw/gitea/data/gitea
Environment=GITEA_CUSTOM=/data/liw/gitea/data/gitea
ExecStart=/data/liw/gitea/gitea web --config /data/liw/gitea/data/gitea/conf/app.ini
Restart=on-failure
RestartSec=5
[Install]
WantedBy=default.target
EOF

loginctl enable-linger $(whoami)    # 登出后仍运行
systemctl --user daemon-reload
systemctl --user enable --now gitea
systemctl --user status gitea
curl -s http://<GITEA主机IP>:3000/api/v1/version   # 期望 {"version":"1.22.x"}
```

**验证**：浏览器打开 `<GITEA>`，能登录管理员账号。

## 四、步骤 ① — 建 Gitea 组织 + 两个仓库

```bash
# 建组织
curl -s -X POST <GITEA>/api/v1/orgs \
  -H "Authorization: token <ADMIN_TOKEN>" -H "Content-Type: application/json" \
  -d '{"username":"<ORG>","visibility":"private"}'

# 记忆仓库（数据，空仓库，不要 auto_init）
curl -s -X POST <GITEA>/api/v1/orgs/<ORG>/repos \
  -H "Authorization: token <ADMIN_TOKEN>" -H "Content-Type: application/json" \
  -d '{"name":"team-memory","private":true,"description":"团队共享记忆仓库","auto_init":false}'

# 工具仓库（代码）
curl -s -X POST <GITEA>/api/v1/orgs/<ORG>/repos \
  -H "Authorization: token <ADMIN_TOKEN>" -H "Content-Type: application/json" \
  -d '{"name":"agent-team-memory","private":true,"description":"team-memory CLI 工具"}'
```

**验证**：`curl -s <GITEA>/api/v1/repos/<ORG>/team-memory` 返回 HTTP 200 JSON。

## 六、步骤 ③ — 初始化记忆仓库 + 推首条记忆

```bash
cd <TOOL_ROOT>
pip install -e ".[mcp]"    # 含 MCP；仅 CLI 可 pip install -e .

python -m team_memory init -p <MEM_ROOT> -n "<TEAM_NAME>" -a <ADMIN>

# 编辑 <MEM_ROOT>/.env
#   GITEA_REMOTE_URL=<GITEA>/<ORG>/team-memory.git
#   GITEA_TOKEN=<ADMIN_TOKEN>          # 或让组员各自配 token
#   TEAM_NAME=<TEAM_NAME>
#   DEFAULT_AUTHOR=<ADMIN>
#   WEB_HOST=0.0.0.0
#   WEB_PORT=8765
#   WEB_PUBLIC_URL=http://<GITEA主机IP>:8765

python -m team_memory capture "团队记忆系统启动" -t project --via claude -a <ADMIN> \
  -p <MEM_ROOT> --note "<TEAM_NAME> 团队共享记忆仓库启动。"

python -m team_memory load --global -p <MEM_ROOT>

cd <MEM_ROOT>
git add -A && git commit -m "chore: 初始化团队记忆仓库"
python -m team_memory sync -p <MEM_ROOT>
python -m team_memory doctor -p <MEM_ROOT>
```

**验证**：

```bash
curl -s -H "Authorization: token <ADMIN_TOKEN>" \
  <GITEA>/api/v1/repos/<ORG>/team-memory/contents | head
python -m team_memory list -p <MEM_ROOT>
```

**验证**：提一个 frontmatter 残缺的 PR → `校验记忆文件` 应失败。

## 九、步骤 ⑥ — 部署团队共享 Web（固定 :8765）

Web **只在记忆仓库所在服务器启动一次**；组员浏览器访问固定链接，**不要各自** `team-memory web`。

### 9.1 配置 `.env`（已在步骤 ③ 写入）

```env
WEB_HOST=0.0.0.0
WEB_PORT=8765
WEB_PUBLIC_URL=http://<GITEA主机IP>:8765
```

### 9.2 注册 user systemd（无需 sudo，推荐）

```bash
mkdir -p ~/.config/systemd/user
cp <TOOL_ROOT>/scripts/team-memory-web.service ~/.config/systemd/user/
# 按实际改 service 内路径: WorkingDirectory / ExecStart / TEAM_MEMORY_ROOT

loginctl enable-linger $(whoami)
systemctl --user daemon-reload
systemctl --user enable --now team-memory-web
systemctl --user status team-memory-web
```

### 9.3 有 sudo 时（多用户共享机器）

```bash
sudo cp <TOOL_ROOT>/scripts/team-memory-web.service /etc/systemd/system/
# 修改 User/Group/路径
sudo systemctl enable --now team-memory-web
```

**验证**：

```bash
curl -s http://<GITEA主机IP>:8765/api/stats
# 浏览器打开 WEB_PUBLIC_URL，能看到记忆列表
# 第二人再跑 team-memory web 应提示端口占用并给出固定链接
```

## 十二、日常运维（管理员）

### 12.1 启停服务

```bash
# Gitea
systemctl --user start|stop|restart|status gitea

# 团队记忆 Web
systemctl --user start|stop|restart|status team-memory-web

# 日志
journalctl --user -u gitea -f
journalctl --user -u team-memory-web -f
```

### 12.2 Web 服务器自动同步（组员 push 后 Web 立即可见）

Web 只读**本地磁盘**，不会自动从 Gitea 拉取。组员 `sync` 推送到 Gitea 后，需在 Web 服务器执行 `git pull`，否则浏览器看不到新记忆。

**推荐：cron 每 5 分钟自动 pull**

```bash
chmod +x <TOOL_ROOT>/scripts/sync-web-server.sh

# 安装定时任务（liw 用户 crontab 示例）
(crontab -l 2>/dev/null | grep -v sync-web-server.sh; \
  echo '*/5 * * * * TEAM_MEMORY_ROOT=<MEM_ROOT> <TOOL_ROOT>/scripts/sync-web-server.sh') | crontab -

# 手动执行一次验证
TEAM_MEMORY_ROOT=<MEM_ROOT> <TOOL_ROOT>/scripts/sync-web-server.sh
tail -5 /tmp/team-memory-web-sync.log
curl -s http://<GITEA主机IP>:8765/api/stats   # total 应随 pull 增加
```

日志默认：`/tmp/team-memory-web-sync.log`（可通过 `TEAM_MEMORY_SYNC_LOG` 改路径）。

**临时手动同步**（不等 cron）：

```bash
cd <MEM_ROOT> && git pull --rebase origin master
```

### 12.3 升级工具版本

```bash
cd <TOOL_ROOT> && git pull && pip install -e ".[mcp]"
# 通知组员: git pull + pip install -e ".[mcp]" + load --global
```

### 12.4 组员误提交到工具仓库

现象：记忆出现在 `agent-team-memory` 而非 `team-memory`，Web 看不到。

处理：

1. 从 Gitea 工具仓库 revert 误提交
2. 在 **team-memory** 仓库用 `save` 或手动迁移 md
3. 提醒组员：`-p ~/team-memory`，禁止 `-p .../agent-team-memory/team_memory`
4. 工具仓库 CI `validate-tool-repo.yml` 会拦截 recurrence

### 12.5 组员 Claude Code「提交一下」不触发

**不要**配 `.claude/settings.json` hooks。正确做法：

```bash
python -m team_memory load --global --tools claude -p ~/team-memory
python -m team_memory check-bridges -p ~/team-memory --tools claude
# 然后新开 Claude Code 会话
```

## 十三、出错处理

| 现象 | 原因 / 修复 |
|---|---|
| Gitea 空响应 / 容器反复重启 | `.env` 里 `DB_TYPE` 写成 `sqlite`，应改 **`sqlite3`** |
| Gitea `:3000` 无监听 | `systemctl --user start gitea` 或 `docker compose up -d` |
| API 401/403 | token 缺 `repository` / `admin:org` |
| push 403 | 组员未加入 `<ORG>` 或 token 无写权限 |
| `不是记忆仓库根(缺少 .team-memory.yml)` | 路径指错；应用 `-p ~/team-memory`，勿用 `.../team_memory` |
| 记忆推了但 Web 看不到 | 推错仓库；或 Web 服务器未 pull → 运行 `sync-web-server.sh` 或检查 cron |
| `web` Address already in use | 正常；全员用 `WEB_PUBLIC_URL`，勿重复启动 |
| 组员 id 撞号 | 两人用了相同英文短名，重新分配 |
| CI 不触发 | runner 未注册；workflow 未拷到对应仓库 |
| Claude 建议配 hooks | 忽略；用 `~/.claude/skills/auto-commit-memory/` |
